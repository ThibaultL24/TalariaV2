# Talaria V3 — implementation and comparison

Branch: `V3`, based on `main` at e22e4ca. Rust API + React/MapLibre.

## Try it

```sh
git switch V3
cargo run -p talaria-api -- serve
cd web
npm ci
npm run dev
```

Use the existing explorer to search/ingest a person. Click **Open V3** on the map.
Direct routes: `/entities/<UUID>/overview`, `/timeline`, `/map`, `/sources`.
Keep an event selected while switching tabs: `?event=<event UUID>`.
The original explorer remains available for comparison.

`serve` applies additive migrations 031 and 032. No destructive rebuild is required.
Configure `DATABASE_URL` with a PostgreSQL 15+ database with PostGIS (16 in CI).
AI keys are server-only environment variables; no credentials are stored in the repository.

## Implemented

- Entity-scoped overview, timeline and GeoJSON endpoints; explicit errors.
- Timeline cursor pagination (same timestamp tie-break by UUID, null dates last).
- Time overlap, event-type and server-side PostGIS bbox filters.
- Read-only `person_timeline_projection`: deterministic lanes and editorial importance.
- Nested semantic zoom thresholds: overview ≥ .8, period ≥ .6, detail ≥ 0.
- Canvas timeline lanes with date ranges, approximate dates and zoom controls;
  accessible chronological event list, paginated as needed.
- Standalone map: debounced viewport requests, cursor traversal and cancellation.
- Source catalog cards retain provider/document/academic/epistemic distinctions.
  Catalog relevance is not represented as event evidence.
- Event detail uses existing source evidence and narrative; map/timeline deep links.
- Persisted light/dark/system preference; light default and editorial palette.
- Explorer event detail no longer mounts Intuition signal controls.
- Search preserves multiple real candidates and their labels; no fabricated result.
- `talaria-ai` contains versioned schemas, hash identity and evidence validation.
- Live person extraction requests strict Structured Outputs, checks exact quotations,
  rejects incomplete/refused responses, and preserves confidence including zero.
- Four concurrent extraction requests maximum; 64KB input and 6000 output-token caps
  for Responses; three attempts for connection/timeout/429/5xx errors.
- `ai_runs` stores completed validated extraction results linked to raw documents,
  with model/provider/version/hash/latency; repeat inputs reuse persisted output.
- Existing deterministic rules, grounding, subject attribution and acceptance gates
  remain mandatory. Cached AI output cannot directly insert canonical events.

Model routing (empty values retain existing provider model fallback):

```dotenv
OPENAI_EXTRACT_MODEL=
OPENAI_JUDGE_MODEL=
OPENAI_SYNTHESIS_MODEL=
```

## API examples

```http
GET /api/v1/entities/<UUID>/overview
GET /api/v1/entities/<UUID>/timeline?from=1851&to=1870&types=residence,travel&resolution=period&limit=200
GET /api/v1/entities/<UUID>/events?bbox=-5,42,9,51&limit=500
```

```json
{
  "events": [],
  "count": 0,
  "pagination": { "next_cursor": null }
}
```

GeoJSON uses the same event UUIDs and an additional `pagination.next_cursor`.
Pass the returned opaque cursor with the **same filters and resolution**. Changed
filters require starting a new traversal. The cursor is not a snapshot guarantee:
new ingestion during traversal can add rows before the current position.

`resolution` defaults to `detail`. An overview deliberately hides minor events;
zooming in retrieves finer detail. A source's historical confidence is independent
of display importance. Unknown dates remain in unbounded detail queries; a temporal
filter excludes unknown dates because overlap cannot be established.

Date ranges are filtered by overlap with requested years. Typed `time` is returned
unchanged; `start_time` is only the ordering projection. Longitude boxes crossing
the antimeridian are explicitly rejected rather than silently misinterpreted.

Errors use `{ "error": "invalid_cursor" }` (400), `entity_not_found` (404), and
`database_error` (500), rather than replacing database failures with empty success.

## Database/performance

031 adds a scoped timeline ordering index and entity/type/time index. Existing GIST
geography index handles bbox. 032 is a view, not a copy of events; its predicates
push down to canonical rows. It does not mutate historical facts or create a
separate ingestion lane. `places` currently counts distinct location labels, not
fully deduplicated geographic identities. Cursor queries return at most 501 rows.

AI cache stores outputs, not keys or raw input copies. Failed or ungrounded outputs
are never cached. Concurrent cache misses can perform duplicate provider work;
unique insertion prevents duplicate cache records but is not a distributed lock.
Current extraction budgets (16 biography chunks per page) remain unchanged.
No performance or cost improvement is asserted without an ingestion benchmark.

## Validation

```sh
cargo test -p talaria-ai
cargo test -p talaria-api -- --test-threads=1 --skip postgres_ --skip extract_then_canonicalize_quality_events_from_fragments --skip v3_db_
cargo test -p talaria-api routes::entity_views   # DATABASE_URL + PostGIS required
cargo clippy -p talaria-ai -p talaria-api --all-targets
cd web
npm test
npm run build
```

V3 CI runs the new DB tests against PostGIS: cursor completeness/null dates,
range overlap, bbox and nested semantic zoom. Frontend tests exercise URL event
selection, Intuition separation and backend time filtering. Offline AI tests reject
fabricated evidence and distinguish model/input cache identities.

## Remaining from the broader proposal

This branch is a usable first V3 implementation, not a claim that all fifteen
proposed work packages have been completed.

- `talaria-ai`: extract the remaining legacy client/presentation/judge prompts out
  of `llm.rs`; enforce structured schemas for those existing tasks too.
- Add document/fragment routing with evaluated recall before enabling exclusion;
  indiscriminate AI pre-filtering can lose historical events.
- Persist typed `ai_judgments`, usage tokens/costs, failed-attempt audit and job budget.
- Add relation extraction, source-context primary/secondary classification and
  multi-source contradiction evaluation with versioned proposals, never opaque merges.
- Extend overview with verified portrait/license, birth/death dates, major places,
  sourced biography and period summaries. Current preview is factual, not generated.
- Improve Canvas collision layout, pointer-centered wheel/pan and aggregate bins;
  add performance fixtures at 2k/5k/10k events and keyboard canvas navigation.
- Localize V3 copy in FR/EN, unify the whole existing UI palette, and show corpus
  document passages directly in Sources (event detail already shows evidence).
- Move all legacy Intuition routes/status under Agora with a compatibility window;
  the current change removes signal UI from Explorer but preserves external API users.
- Validate real OpenAI provider calls and end-to-end live ingestion with operator
  credentials; offline tests never consume the user's OpenAI balance.
